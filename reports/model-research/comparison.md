# Existing spoiler detectors: decision before further training

Research date: 2026-10-02. Scope: plot-spoiler detection for headlines, comments, reviews and transcripts. Clickbait-spoiling systems that generate an answer to a teaser headline are a different task and are excluded.

## Recommendation

**Pause additional fine-tuning until existing checkpoints have been evaluated on independent product examples.** Start with **Zritze RoBERTa LR1 and Zritze BERT**: both have standard Transformers configurations, consistent binary label maps, tokenizer assets and safetensors. Add **bhavyagiri RoBERTa** as the better-documented IMDb baseline, subject to an approved way to handle its legacy `.bin` artifact. Keep **eesuan DistilBERT** as the smaller-model candidate, blocked on a contradictory label mapping. These are candidates for evaluation, not demonstrated production winners.

A review classifier can provide a useful initial risk score. None of the inspected releases establishes reliable performance across all four product surfaces, or conditions its decision on a viewer's watched episode/chapter. Do not interpret a classifier score as proof that a fact is true, belongs to the target title, or is new to that viewer.

For recovered training notebooks, exact subset class counts, replication gaps and a proposed hosted GPU pilot, see [replication-recipes.md](replication-recipes.md).

## What was actually verified

Public Hugging Face APIs supplied repository revisions, file inventories, file sizes and license metadata. Configuration JSON, tokenizer configuration and model cards were read at pinned revisions. **Four candidate weight URLs returned HTTP 200 to HEAD requests**, with lengths matching repository metadata. This verifies public availability, not tensor integrity, successful loading, prediction quality or checkpoint/card correspondence. No weights were downloaded; no model inference, training, external code or pickle execution occurred.

The companion `metadata-snapshot.json` contains exact URLs, revisions, configurations, cards and HEAD results for ten repositories. `supplemental-sources.json` records dataset metadata, additional documentation and official GitHub trees/releases. `collect_metadata.py` can refresh the model-card/configuration inventory; HEAD and supplemental checks were separate, so the script alone does not reproduce those checks. Mutable source URLs were observed on the research date; use pinned revisions below for candidate evaluation.

**Metric warning:** bhavyagiri’s 0.773021 is weighted F1 according to recovered training code, not spoiler-class F1. With 1,509 positives/5,740 validation rows and the reported accuracy (1,244 errors), spoiler-class F1 cannot exceed **0.708118** for the same predictions. The actual spoiler F1 is unknown. See the replication supplement for the derivation and artifact-version caveat.

### Label and packaging blockers

- **eesuan:** [pinned config](https://huggingface.co/eesuan/imdb-spoiler-distilbert/blob/dbcc9f1883a6385175bbda4e4ac6f9902cafd01e/config.json) declares `id2label={0: NON-SPOILER, 1: SPOILER}` but `label2id={NON-SPOILER: 1, SPOILER: 0}`. These are not inverses. Merely editing one map does not establish which class each trained logit represents. Recover training label encoding or obtain author confirmation, then sanity-check both orientations against independently labeled examples before evaluation. Keep the original metadata and document any adapter override.
- **bhavyagiri:** semantic mapping is a card claim, not embedded configuration. A future adapter must explicitly map logits according to that claim and verify it. Public availability of `.bin` does not establish a safe, executable integration path under the present restrictions.
- **Zritze LR3:** [configuration and tokenizer files](https://huggingface.co/Zritze/imdb-spoiler-robertaOrigDatasetLR3/tree/5477341cad8649dc0e1b3386af551a343db80faa) identify a RoBERTa model but a `DistilBertTokenizer` with BERT special tokens and `vocab.txt`. Exclude this package until training/tokenizer provenance is resolved. Substituting a RoBERTa tokenizer without evidence could change the trained input semantics.

## Research systems versus ready checkpoints

**SpoilerNet (ACL 2019): research architecture, no verified ready checkpoint.** Uses hierarchical bidirectional GRUs, word attention, sentence context, item-specific word features and book/user bias terms for binary sentence labels. Goodreads user spoiler tags provide fine-grained supervision; the paper also studies TV Tropes. Its reported Goodreads ROC AUC .919 measures ranking rather than deployable threshold accuracy. Text-only headlines lack the review context and book/user history that motivate the architecture. [Primary paper](https://aclanthology.org/P19-1248/); [author's architecture/results poster](https://mengtingwan.github.io/paper/acl19_mwan_poster.pdf).

The [author repository](https://github.com/MengtingWan/spoiler) at inspected tree `669a5014c4f678100ffd81fe641f613082fd4479` contains only `.gitignore` and `LICENSE`, with no releases. It is a placeholder, **not verified implementation code or weights**. The separate [Goodreads repository](https://github.com/MengtingWan/goodreads) is a data-resource lead, not evidence of a pretrained detector. Do not confuse a reimplementation with the authors' trained model.

**Spoiler in a Textstack (2021): code available, trained artifact not verified.** Fine-tunes BERT/ALBERT/ELECTRA for single-sentence and sequential-sentence binary classification; experiments use weighted binary cross-entropy and optional genre information. TV Tropes Movies uses 128 wordpieces; single-sentence Books/Goodreads uses 96; the sequential Books setup uses up to five sentences/512 tokens. The paper reports ELECTRA TV Tropes Movies test ROC AUC .8120 and accuracy .7406. Goodreads experiments distinguish a balanced tuning subset from full-data evaluation. These are not headline/transcript metrics. [Primary full text](https://arxiv.org/html/2112.12913v1).

The [linked author's implementation](https://github.com/rzepinskip/spoiler-detection) contains training, testing and dataset modules (Python 3.7 prerequisites). At tree `70448409e570bfbcfae7cbbf0697c697de62eb4a`, no weight artifacts or releases were found, and its README offers datasets rather than a model download. No license file is present in that inspected tree. A reproduction would require more work than evaluating existing HF checkpoints.

**GUSD (ECML PKDD 2025): code/data workflow, no verified trained release.** Combines text representations, genre aggregation, a review-history graph for user bias, and genre-aware mixture-of-experts classification. Binary review labels come from LCS and Kaggle IMDb; the paper describes a random review-level 7:2:1 split. Such splits do not establish unseen-title/user generalization. [Primary paper](https://arxiv.org/html/2504.17834v3).

The [official repository](https://github.com/AI-explorer-123/GUSD) has source and training commands, no weight files in its inspected complete tree, and no releases. README declares MIT; LCS requires an access request, and IMDb preprocessing is linked externally. [Configuration code](https://github.com/AI-explorer-123/GUSD/blob/main/Code/config.py) selects frozen BGE-large features for IMDb and RoBERTa/fine-tuning for LCS. It supplies default 20 epochs/LR 1e-4, but defaults are not proof of the exact paper run. No standalone tokenizer/input-limit contract for a released detector exists here. Dependencies on genres and user histories make this a poor first fit for arbitrary anonymous comments. External dataset archives were not downloaded or searched for hidden weights.

“No verified checkpoint” means none was found in the inspected repository tree, releases or documented model-download instructions; it does not prove no artifact exists elsewhere.

## Product fit and evaluation risks

| Surface | How an existing checkpoint could be tried | Failure modes to measure |
|---|---|---|
| Headlines | Score the headline; separately test headline plus available title/context. | Short fragments, missing referents, puns, questions and speculation; review-language domain shift. Never import clickbait-answer-generation metrics. |
| Comments | Score individual comments and compare with a small parent-context window. | Pronouns, sarcasm, memes, quoted spoilers, false theories, title ambiguity and cross-title references. Context concatenation is a new policy to validate. |
| Reviews | Closest training domain. Compare bounded whole reviews against overlapping windows. | One spoiler anywhere versus overall review labels; spoilers beyond first 512 tokens; “no spoilers” phrases and site markup shortcuts. |
| Transcripts | Segment into overlapping sentence/utterance windows with timestamps; preserve attribution. | ASR errors, unpunctuated speech, long-range references, quoted dialogue and length-driven false alarms. No inspected release establishes transcript performance. |

**IMDb overlap is the principal evaluation trap.** Bhavyagiri and eesuan explicitly share the same subset. Zritze's naming is suggestive but insufficient to identify its exact rows. TcJordan's different source collector and leoole's IMDb-derived examples do not guarantee disjointness from local IMDb data. A high score on a local IMDb holdout may reflect unknown training contamination. The subset's [dataset card](https://huggingface.co/datasets/bhavyagiri/imdb-spoiler) lists 28,696 rows; API inventory exposes train/valid CSVs, not an independent test split. The recovered author notebook verifies stratified 5% sampling and an 80/20 review-level split. A direct CSV audit found one exact text shared across splits; no title/user grouping is performed. See the replication supplement.

Accuracy on balanced data, binary F1 with unspecified averaging, three-class macro F1 and sentence-level ROC AUC are not interchangeable. User-supplied spoiler flags reflect differing spoiler standards; absence of a flag is not necessarily a carefully judged negative. Unknown checkpoint selection, repeated validation tuning and shared titles/users further limit comparisons. No metrics in this report were independently reproduced, and no performance ordering should be inferred from the table values.

License strings above are **publisher metadata, not legal guarantees**. Model weights, base encoders, code and underlying review text can have separate terms. Missing metadata is unresolved provenance, not a permissive license; a model-card tag does not settle rights to IMDb review content. This work did not perform a legal review.

## Concrete next decision, without training

1. **Use the already completed product benchmark and its existing holdout protocol.** If coverage gaps remain, supplement it with fresh items per surface and a separate calibration set. Use human labels and preserve source, title, length, explicit/implicit spoiler, and viewer-progress assumptions. Include enough positives and difficult negatives; keep naturally sampled and deliberately balanced/challenge results separate. Prefer new/non-IMDb content and unseen titles. Group all windows from a document into the same split, deduplicate, and isolate final test labels from threshold selection.
2. **Evaluate the two consistent safetensors candidates first**, at the pinned revisions. Add bhavyagiri only after an acceptable artifact-loading/export path is established, and eesuan only after class orientation is resolved. Test label semantics and tokenizer compatibility before trusting aggregate scores. This report does not authorize or perform weight downloading.
3. **Choose thresholds on calibration data**, separately considering each surface. Measure spoiler precision/recall, PR-AUC, confusion matrices, false-block rate on clean text and confidence intervals. Report per-surface and unseen-title results, latency and memory on the actual target hardware. Set product tolerances before looking at final test results; the acceptable recall/false-block tradeoff is not specified yet.
4. **Test segmentation before retraining.** Compare first-window truncation with overlapping windows and a documented aggregation rule. Maximum window score is a useful hypothesis, but increases false-positive opportunities for long transcripts. Calibrate and evaluate at document level as well as window level; a window score is not a verified spoiler span.
5. **Fine-tune only for a measured gap.** If an existing checkpoint meets agreed product tolerances, use it with the validated preprocessing/threshold policy. If calibration or segmentation fixes the gap, retain its weights. If short-context language, implicit spoilers or ASR remain systematic failures, collect labels for those failures before targeted adaptation. If viewer progress is essential, investigate title/progress context or retrieval; another IMDb binary fine-tune alone does not add that missing information.

The current blockers are unresolved label/provenance issues for some releases and absent product-domain evaluation—not lack of public trained models.
